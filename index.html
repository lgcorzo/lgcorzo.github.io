Dark Gravity: an autonomous software factory, checked against evidence

Dark Gravity is an experimental system that turns a GitHub issue into a reviewed pull request. AI agents do the work inside locked-down sandboxes, and a human always decides what is merged.

It is built for engineers who want to see how autonomy and strict controls can live together. It is a one-person lab project, not a product.

Honest status: latest release is v0.2.8. A mission has completed end to end on the lab cluster. Long soak tests and multi-node failure drills are not published.

What do the status tags mean?

The same four tags are used on every page.

DesignedDescribed in specs or wiki only.
ImplementedCode exists and has tests.
DeployedRunning in the cluster.
VerifiedConfirmed by a test or evidence file, which is linked.

Compliance wording: the controls are readiness measures. No third-party certification (EU AI Act, SOC 2 or other) is claimed.

Which projects are there?

The GitHub account has 72 repositories (64 public) and 42 of them are forks, counted on 2026-10-31. These are the ones that matter most, grouped by job.

The factory

  • rust_CACD_autonomous_factory: the core. Hatchet pipeline, agents, CLI and MCP server.
  • speckit-superpowers-bridge: hands a written spec to a test-first coding workflow.
  • mlops-python-package: machine-learning pipeline standard used by the lab.

Memory and documentation

  • semantica: records where each AI-made artifact came from.
  • R2R-Engine: retrieval engine that gives agents context.
  • deepwiki-rs and openwiki: generate documentation from code.

Gateway and storage

  • dark-litellm: one gateway to many language models, with cost tracking.
  • operator: runs S3-compatible storage inside the cluster.

What do the terms mean?

ADR
Architecture decision record. A short document that states one design decision and why it was made.
CRD
Custom resource definition. It adds a new kind of object to Kubernetes, here the AgentWorkspace.
DAG
Directed acyclic graph. A set of steps with a fixed order and no loops. Hatchet runs the mission as a DAG.
FinOps
Tracking and limiting what a system spends, here on language-model calls.
gVisor
A sandbox that gives a container its own user-space kernel, so code in it cannot talk to the host kernel directly.
GitOps
Changing a running system only by committing files to Git, which a tool such as Flux then applies.
HITL
Human in the loop. A person must approve certain steps. Here, only a person merges to main.
Hatchet
The workflow engine that runs and retries the mission steps.
Kafka
A message system. Missions and agent events travel through Kafka topics.
MCP
Model Context Protocol. A standard way for an AI tool to call outside tools. The factory runs an MCP server.
NHI
Non-human identity. A signed identity for a program, so its actions can be traced.
SAST
Static application security testing. Reading code for security flaws without running it.
SDD
Spec-driven development. Write the specification and plan first, then generate code from them.
