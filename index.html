Industrial AI Systems • Autonomous Software Engineering • Cloud-Native Architecture

An autonomous software factory in Rust and Kubernetes where AI agents propose pull requests in isolated sandboxes and a human decides the merge

Research Question Can autonomous coding agents be contained within deterministic security boundaries and strict budget limits, while keeping human-in-the-loop merge governance?

Dark Gravity is an experimental research system that turns a GitHub issue into a verified PR. Autonomous agents do the implementation work inside locked-down gVisor sandboxes, and a human maintainer always makes the merge decision.

It is built for engineers exploring how agentic autonomy, micro-sandboxing, and strict operational controls can live together. It is a personal engineering research lab, not a commercial product.

What do the status tags mean?

Every claim, component, and capability on this site carries one of four explicit status tags:

VerifiedConfirmed by published test suites or empirical evidence files.
DeployedRunning and reconciled in the Kubernetes cluster or production CI/CD workflows.
ImplementedCode exists in workspace, compiles cleanly, and passes automated unit/integration tests.
DesignedDescribed in specifications or wiki architecture only; live cluster verification in progress.

Compliance wording: all controls are architectural readiness measures. No third-party certification (EU AI Act, SOC 2 or other) is claimed.

What works today? (Actual Factory Status)

Each capability below is stated in plain language with its verification tag, evidence source, and expandable technical details. Checked on 2026-10-31 against the repository and the lab cluster.

CapabilityStatusPlain-Language Summary & Evidence
Rust 5-crate workspace & quality gates Verified The core factory codebase compiles without warnings and passes all linter, adversarial, and unit-test gates.
Technical details & evidence source
Source: evidence/verified_status.json (commit 9302482). Architecture follows a 5-crate onion model (factory-core, factory-application, factory-infrastructure, factory-mcp-server, factory-cli) on Rust Edition 2024 (rustc 1.85+).
Forensic memory zeroization Implemented Verified Ephemeral credentials and MCP tokens in RAM undergo an automated null-byte wipe on drop to prevent forensic memory dumping.
Technical details & benchmark context
Credential carriers derive Zeroize and ZeroizeOnDrop. Criterion micro-benchmarks measure this forensic wipe at 54.2 ns (0.0542 µs) on AMD x86_64 hardware. Source: benches/memory_zeroize_bench.rs. Reproduce via cargo bench --bench memory_zeroize_bench.
5-phase durable mission pipeline Deployed Missions execute a 5-step workflow (plan, execute, validate, review, deliver) on Hatchet with automatic task retries and state checkpointing.
Technical details & worker deployment
Workers run release image 6beb333 (v0.2.8) in namespace agents. Hatchet coordinates rustant:plan, zeroclaw:execute, zeroclaw:validate, rustant:review, and factory:deliver. Checkpoints persist to PostgreSQL and MinIO S3.
Micro-sandbox limits enforced at admission Deployed Untrusted code execution pods are strictly capped to at most 30Mi RAM and 250m CPU, blocking runaway processes before pods can start.
Technical details & admission policies
Enforced by Kubernetes ValidatingAdmissionPolicies dg-sandbox-bounds-jobs and dg-sandbox-bounds-pods. Sandbox containers run under RuntimeClass=gvisor (gVisor runsc kernel emulation) with readOnlyRootFilesystem: true and dropped capabilities. Source: deploy/policies/.
AgentWorkspace custom resource (ADR-008) Deployed Implemented A declarative Kubernetes specification defines the repository, target branch, and immutable resource envelope for agent workspaces.
Technical details & controller state
The agentworkspaces.darkgravity.io CRD is installed in the cluster. The operator controller is implemented in factory-cli using kube-rs v0.93. Active reconciliation loop operates within the CLI binary.
FinOps budget limits and spend velocity guard Implemented Missions are halted automatically if daily spend reaches 90% of the limit or if expenditure accelerates faster than $1.00 per minute.
Technical details & LiteLLM headers
Implemented in finops.rs with unit tests. Default threshold: halts at $45.00 of $50.00 daily budget. Outbound requests inject LiteLLM virtual tags (x-vtags-team, x-vtags-epic). Halting triggers a budget-exceeded Kafka event.
Cryptographic Non-Human Identity (NHI) Implemented Autonomous agents sign every mission intake, tool call, and code diff with asymmetric keypairs for tamper-evident provenance.
Technical details & W3C credentials
Implemented via Ed25519 asymmetric keypairs (ed25519-dalek v2) producing W3C Verifiable Credential envelopes (Ed25519Signature2020). Source: crates/factory-core/src/security_nhi.rs and evidence/security-tests.md.
Multi-node chaos drills and soak testing Designed Multi-node cluster failure drills and continuous multi-day soak tests are architecturally planned but not yet published as verified facts.
Technical details & reliability status
Single-worker kill recovery is verified in reliability-tests.md. Chaos Mesh broker-loss and multi-node failure injection scenarios remain in Designed status.

Which projects are there?

I maintain 64 public repositories on GitHub (22 original source repositories + 42 maintained forks), verified on 2026-10-31. Here are the core projects grouped by function:

The Factory

  • rust_CACD_autonomous_factory: the core system. Hatchet pipeline, agent coordinators, CLI, and MCP server.
  • speckit-superpowers-bridge: hands structured specs to test-first agent coding workflows.
  • mlops-python-package: machine-learning pipeline standard used by the lab.

Memory & Documentation

  • semantica: tracks provenance and semantic relationships across generated artifacts.
  • R2R-Engine: retrieval-augmented generation engine supplying context to agents.

Gateway & Storage

  • dark-litellm: sovereign proxy and router for multi-model governance and FinOps tracking.
  • operator: runs S3-compatible object storage inside the Kubernetes cluster.

Open-Source Governance

I maintain 42 dependencies as independent forks to guarantee SDD interface stability, zero-warning linter gates, and automated security patching. Read the full rationale on the Fork policy page or inspect all repositories on GitHub.

What do the terms mean? (Glossary)

ADR
Architecture Decision Record. A short document stating one architectural decision, its rationale, and consequences.
CRD
Custom Resource Definition. Extends Kubernetes with custom object types, here the AgentWorkspace standard.
DAG
Directed Acyclic Graph. A finite sequence of steps with fixed dependencies and no circular loops. Hatchet executes missions as a DAG.
FinOps
Cloud and language-model financial operations: tracking, attributing, and strictly limiting token expenditures.
gVisor
A sandboxing runtime (runsc) that provides containers with an isolated user-space kernel, preventing direct host kernel calls.
GitOps
Operating declarative infrastructure by reconciling cluster state directly from versioned Git commits (e.g. FluxCD).
HITL
Human-in-the-Loop governance. Critical actions require human approval. Autonomous agents cannot merge to default branches.
Hatchet
A durable workflow orchestration engine that coordinates and retries distributed agent mission tasks with checkpointing.
Kafka
Distributed event streaming platform. Missions, agent events, and telemetry travel through dedicated Kafka topics.
MCP
Model Context Protocol. An open standard for AI agents to securely invoke external tools and fetch contextual data.
NHI
Non-Human Identity. Asymmetric cryptographic credentials (Ed25519) signed by autonomous workers to ensure verifiable action lineage.
SAST
Static Application Security Testing. Automated static analysis inspecting code diffs for security vulnerabilities before pull request delivery.
SDD
Spec-Driven Development. Writing formal specifications, architectural plans, and test contracts before generating code.
SSOT
Single Source of Truth. The practice of structuring architecture so every configuration or domain entity is defined in exactly one place.
