Every entry answers five questions

  1. What did I want to verify?
  2. Which architecture and configuration did I use?
  3. What actually happened?
  4. What did I learn and which limitations did I find?
  5. What would I do differently in the next experiment?

From lab to industry, without mixing environments

Learnings are kept in three clearly separated categories.

A · PERSONAL EXPERIMENT

Code, models, agents, orchestration, storage and deployments under my own control. Free to iterate.

B · REUSABLE PATTERN

The general lesson: state persistence, agent evaluation, permissions, traceability, recovery, context management.

C · ENTERPRISE APPLICATION

Assessed against real requirements, security and architecture constraints through the corresponding internal process.

No internal configurations, proprietary code, customer data, credentials, identifiable incidents or confidential architecture details are published here. A pattern that works in the lab is not assumed ready for production: the lab reduces uncertainty, enterprise adoption requires its own evaluation.

Autonomous engineering lab

Dark Gravity — a lab for autonomous engineering

The main project for experimenting with automating the development cycle: specification, planning, code generation, validation, isolation and delivery. It publishes architectural decisions, runs, limitations and negative results. See the repository README for what is implemented, what is deployed, what is still experimental and what is pending.

Explore the architecture Fork policy Source on GitHub

THE QUESTION

How far can the software lifecycle be automated when agents hold credentials, run untrusted code and act with limited oversight?

THE EXPERIMENT

Narrow agent roles, disposable sandboxes, short-lived credentials and a durable workflow, tested mission by mission.

THE LEARNING

What works, where it fails and which patterns are worth evaluating elsewhere. A human gate stays before every merge.
