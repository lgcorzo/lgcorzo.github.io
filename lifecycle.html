Autonomous Mission Lifecycle

How missions transition from human requirements to verified pull requests: Spec-Driven Development (SDD), durable Hatchet DAG steps, isolated gVisor sandboxes, and human-in-the-loop review.

Status taxonomy

Every operational phase and control across this page carries one of four explicit verification tags:

Verified Confirmed by automated CI suites or published evidence files.
Deployed Running and active in live cluster environments.
Implemented Code written, unit-tested, and tracked in the Rust workspace.
Designed Documented in ADRs, specs, or wiki; full validation pending.

Who executes missions and who holds authority?

Dark Gravity organizes work across specialized agent personas, bound by strict non-human identity (NHI) credentials and four human-in-the-loop (HITL) checkpoints.

Rustant — Product Owner & Planner

Queries semantic memory (R2R GraphRAG), applies constitution rules, executes Spec-Kit workflows, and compiles atomic, dependency-ordered tasks into tasks.md.

Verified

ZeroClaw — Developer & Code Surgery

Consumes tasks through the speckit-superpowers-bridge, performs AST code modifications inside gVisor sandboxes, and validates test suites.

Verified

DevOps Agent & Jules Remediator

Classifies build failures, matches error patterns, and runs closed-loop automated pipeline remediation without modifying production deployment branch states.

Deployed

DocAgent — AST Living Documentation

Generates architecture descriptions, validates relative path links, and tracks orphan symbol rates (OSR < 5%) to keep wikis synchronised with code.

Implemented

Human-in-the-loop governance checkpoints

Automation handles routine development tasks, while human authority governs strategic direction, architecture, and production merges:

Checkpoint Trigger & Responsibility System Enforcement Status
1. Strategic Injection Human engineer opens an issue tagged autonomous-mission with scope and operational boundaries. GitPlatformPoller verifies labels and signs Ed25519 NHI credentials before dispatching to Kafka. Verified
2. Plan Scrutiny Engineer can review and refine generated spec.md and plan.md contracts via comment directives. Directives like @darkgravity /refine pause execution until contracts match engineer intent. Verified
3. Exception Override Circuit breakers fire if diff hashes repeat, tests fail 3 times, or spend exceeds 90% daily budget. Active DAG execution is halted immediately and JIT credentials are revoked pending human diagnosis. Verified
4. Mandatory Merge Gate All tests and SAST checks pass with green status; pull request is presented for merge. Strict HITL rule: Automated merging to main is blocked. A human engineer must review and merge manually. Verified

How do missions advance through durable DAG phases?

The mission pipeline runs on the Hatchet orchestration engine (cacd-mission-dag), checkpointed in PostgreSQL and MinIO S3 to survive node crashes or pod restarts.

Phase 1: Ingestion & Planning

Incoming events on Kafka topic mission-input trigger the Hatchet workflow. Rustant fetches relevant architecture context, initializes Spec-Kit, and creates dependency-ordered tasks in tasks.md.

Verified

Phase 2: Code Surgery

ZeroClaw spawns an ephemeral Kubernetes Job with RuntimeClass=gvisor. Sandboxed tools mutate code files, adhering to project coding guidelines and memory bounds.

Verified

Phase 3: Sandbox Validation

Inside the user-space gVisor kernel, test suites and linters run to verify implementation correctness. No network egress is permitted except to authorized internal registries.

Verified

Phase 4: Security Review (SAST Judge)

The code diff is evaluated by an LLM-as-a-Judge security audit tool. The reviewer checks against CWE vulnerabilities, enforcing a pass score threshold ≥ 8.0/10.0 and recording causal lineage.

Verified

Phase 5: Delivery & Handoff

The delivery task pushes the branch, creates a formal PR linking the originating issue (Closes #ID), and posts a test evidence summary for human inspection.

Verified

How are pipeline errors remediated?

When CI pipelines fail or security scanners detect vulnerabilities, the autonomous factory triggers closed-loop remediation workflows:

Closed-loop remediation flow

Diagnostic log parsing extracts root causes (e.g., dependency deprecations, linter errors). Synthetic remediation missions are dispatched to mission-input. The circuit breaker caps fixes at 3 attempts and monitors AST diff hashes to prevent oscillating edits.
