Why We Fork Principal Open-Source Projects for the Autonomous Factory

An autonomous software factory (rust_CACD_autonomous_factory + Jules_remediator) executes multi-agent planning, code synthesis, AST documentation, and Kubernetes deployments without manual hand-holding during intermediate steps. Depending directly on unpinned upstream rolling branches or third-party container registries introduces four unacceptable operational risks:

RATIONALE 1 • CONTRACT STABILITY

Deterministic SDD & Agent Protocols

Our agents rely on exact CLI flags, JSON handoff schemas, and guard scripts across spec-kit, superpowers, speckit-superpowers-bridge, and adk-rust. Forking prevents upstream CLI breaking changes from derailing active Hatchet DAG missions.

RATIONALE 2 • RAPID CVE REMEDIATION

Zero-Wait Security Patching

Upstream AI & RAG frameworks (semantica, dark-litellm, CodeWiki, openwiki, deepwiki-open) frequently carry unpatched transitive CVEs in Python/Node dependency trees for weeks. In our forks, Dependabot + Jules + Project 6 patch and lock them within hours.

RATIONALE 3 • CODE QUALITY RULES

Enforcing Lab-Wide Engineering Standards

Upstream projects vary wildly in CI rigor. By maintaining our own forks, we enforce uniform AGENTS.md contracts, custom CodeQL workflows, SHA-256 hash-pinned audit manifests, clippy -D warnings / ruff gates, and AST-based OpenWiki documentation.

RATIONALE 4 • UPSTREAM INDEPENDENCE

Insulation from Vendor Policy Shifts

When upstream vendors alter licensing, strip administrative UI features (as occurred in upstream MinIO), or deprecate container registries, our 38 decoupled Go storage/SIMD forks continue compiling hermetically to ghcr.io/lgcorzo/*.

The 4 Pillars of Code Quality & Supply-Chain Governance

Every forked and original repository in the lab is governed by explicit supply-chain and code quality rules documented in @lgcorzo/docs and repository-level AGENTS.md constitutions:

PILLAR 1

Git Remote & Branch Hygiene

Default branches (main) push exclusively to github.com/lgcorzo/*. Merged or superseded feature and Dependabot branches are automatically pruned both remotely and locally to keep a clean, single-source-of-truth revision graph.

PILLAR 2

Strict Linting, Type & Audit Gates

PRs must pass language-specific quality gates (cargo clippy -D warnings, ruff, pytest, shellcheck), custom codeql.yml static analysis, and pip-audit / cargo audit against hash-pinned lockfiles.

PILLAR 3

Hermetic Builds & Zero-:latest Policy

External registries (quay.io, docker.io) are replaced by hermetic GitHub Actions builds published to ghcr.io/lgcorzo/* with immutable semantic tags (v*.*.*-lgcorzo.*).

PILLAR 4

No Blind Upstream Rebases & HITL

Upstream commits are treated as untrusted third-party inputs. No automated force-rebases occur; all changes flow through PR verification, and core factory repositories enforce strict Human-in-the-Loop (HITL) merge approval.
