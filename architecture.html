Resource Efficiency

How to Run an Autonomous Factory on Limited Resources

Dark Gravity is engineered to thrive on constrained bare-metal or modest cloud instances by replacing heavyweight VMs with micro-sandboxes, memory-zeroed processes, and predictive FinOps guards.

📦

gVisor Micro-Sandboxing (≤ 30 MiB RAM)

Traditional VM-based sandboxes require gigabytes of RAM and take 30+ seconds to boot. Dark Gravity uses gVisor (runsc):

  • User-Space Kernel: gVisor intercepts Linux syscalls in user-space, preventing kernel exploits without full virtualization overhead.
  • Aggressive Resource Clamps: Agent sandbox pods are restricted to RAM ≤ 30 MiB and CPU ≤ 250m. Sidecars are restricted to RAM ≤ 20 MiB and CPU ≤ 100m.
  • Sub-Second Boot Time: Micro-sandboxes launch in milliseconds, allowing hundreds of tests to execute concurrently on a single commodity node.
💰

Predictive FinOps & Velocity Clamping

Uncontrolled LLM agent loops can bankrupt a development budget in hours. Dark Gravity enforces hardcoded financial guardrails:

  • Virtual Tags (Vtags): LiteLLM injects HTTP tracking headers (x-vtags-team, x-vtags-epic, x-vtags-cost_center) to attribute every token.
  • Spend Velocity Guard: If burn rate exceeds +$1.00 / 60 seconds, the circuit breaker trips instantly.
  • HardStop Budget Cap: When 90% of the daily budget ($45 of $50) is consumed, the Hatchet DAG halts, JIT tokens revoke, and a Kafka alert is broadcast.
